Its handshake follows the same pinning policy as `ApiClient`: when pinning is in effect it connects through the pinned `HttpClient` from `SslPinning.createHttpClient()`, so a `wss://` server whose certificate the fingerprints do not name is refused. Pass `sslPinning:` to use a different policy. Its log lines and every error `connect` throws name the URL redacted - userinfo and query values whose key names a secret replaced - so a realtime token does not reach a crash report. In a staging or production release, `connect` refuses any URL that is not `wss://` (a `WebSocketChannelException`, nothing opened), as `main()` refuses a non-`https` `BASE_URL`; development, debug and profile builds still accept `ws://`.
