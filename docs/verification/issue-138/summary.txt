Known limits, unchanged by this issue
-------------------------------------
* The walk sees the tree at the moment it runs. A file dropped in afterwards
  ships until something runs the check again.
* In CI the walk is weaker still: a gitignored .env never reaches the runner,
  so the run that catches this case is the local one (audit_template.sh, the
  pre-push hook, or a release checklist step).
* The guard is still not on the release-build path - scripts/ci/build_all.sh
  and the deploy workflows can build a tree it never ran against. That is
  koniz-dev/flutter-starter#135, deliberately not fixed here. Directory paths
  now resolve relative to the pubspec's own directory, so #135 can point the
  guard at another tree without changing it.
* Matching is by file name only. A secret inside an innocuously named file
  (assets/config/app_config.json holding an API key) is not detected, and that
  is the accepted cost of not firing on ordinary configuration.
