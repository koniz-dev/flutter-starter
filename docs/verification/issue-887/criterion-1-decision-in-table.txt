635:The rule fails closed. Only failures known to be transport trouble keep the session, because a session that can never refresh would otherwise stay up indefinitely. A token store that cannot be read is not transport trouble: the refresh cannot run without it, so it ends the session too. Outside a refresh, a failed read only fails the request it was reading for, with the store's exception; the session is untouched. A custom refresher should therefore tag a dead refresh token with `REFRESH_TOKEN_EXPIRED`, and return its transport failures as `NetworkFailure` or `ServerFailure`. When the session is kept, queued requests are rejected rather than replayed, and the next 401 starts a fresh refresh. That teardown clears the **same three persisted things** `AuthRepositoryImpl.logout()` clears - the tokens, the cached user blob, and the HTTP response cache (see [CacheInterceptor](#cacheinterceptor)) - so a session that ends by token expiry leaves the device in the same state as one the user ended by tapping "log out". A fourth step then notifies `sessionSink`, so the running app drops the in-memory session too rather than presenting a signed-in UI backed by storage that is now empty.
