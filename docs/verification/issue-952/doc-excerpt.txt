--- configuration.md troubleshooting
569: ## Best Practices & Troubleshooting
570: 
571: 1. **Never commit `.env` files**: They contain sensitive information and are gitignored
572: 2. **Never bundle `.env` as an asset**: assets are not build-mode scoped, so it ships to every user. See [Never ship a secret in the bundle](#never-ship-a-secret-in-the-bundle)
573: 3. **Use `.env.example` as a template**: Commit this file with placeholder values
574: 4. **Use `--dart-define-from-file=.env` for local development**: same file, same convenience, nothing bundled
575: 5. **Use `--dart-define` for CI/CD**: keeps values out of the asset list; supply them from the CI secret store, never from a committed file
576: 6. **Keep real secrets out of every client build**: on web that is not a preference but a fact - serve them from your backend instead
577: 7. **Set environment-specific defaults**: Let the system handle defaults based on environment via `AppConfig`.
578: 
579: ### Troubleshooting missing configuration
580: - **`.env` values ignored?** Expected: `.env` is not an asset, on purpose. Pass `--dart-define-from-file=.env` instead, and check the keys exist in `lib/core/config/dart_defines.dart`. Declaring `.env` under `flutter: assets:` would make `flutter_dotenv` find it - and publish it in every build; `dart run tool/check_env_assets.dart` fails if you do.
581: - **`--dart-define` value ignored?** Check that the key exists in `lib/core/config/dart_defines.dart`. A key missing from that table is ignored on every platform, web included. `--dart-define` values are baked in at compile time: change one and you must rebuild, not hot reload.
582: - Changed `.env` or a `--dart-define`? Hot reload and hot restart keep the old values: stop the app and run `flutter run` again.
583: - `AppConfig.printConfig()`, which `main()` calls in debug builds, prints the values in effect: check its output in the console.
